## SMT 支持

### 取指策略 (SMTFetchPolicy)

| 策略 | 描述 |
|------|------|
| RoundRobin | 轮询取指 |
| IQCount | 基于 IQ 占用率 |
| LSQCount | 基于 LSQ 占用率 |
| BranchCount | 基于分支计数 |

### IQ 分配策略 (SMTQueuePolicy)

| 策略 | 描述 |
|------|------|
| Partitioned | 分区分配 (均匀分配给各线程) |
| Dynamic | 动态共享 (所有线程共享全部条目) |
| Threshold | 阈值控制 (单线程可用全部，多线程按阈值分配) |

### 提交策略 (CommitPolicy)

| 策略 | 描述 |
|------|------|
| RoundRobin | 轮询提交 |
| OldestFirst | 最老指令优先 |

## 核心组件说明

### BAC (Branch & Address Calculation)

- **分支预测单元 (BPredUnit)**:
  - BTB (Branch Target Buffer): 分支目标缓冲
  - 方向预测器：TournamentBP (混合预测器)
  - 返回预测器：ReturnAddrStack

- **FTQ (Fetch Target Queue)**:
  - 解耦前端的核心组件
  - 缓冲预测的取指目标
  - 支持预取机制

### Fetch (取指)

- **主要功能**:
  - 从 I-cache 获取指令
  - 分支预测查询
  - 处理 cache miss 和重试
  - 指令解码 (创建 StaticInst)

- **关键参数**:
  - fetchWidth: 每周期取指条数
  - fetchBufferSize: 取指缓冲区大小
  - numFetchingThreads: SMT 取指线程数

### Decode (译码)

- **主要功能**:
  - 验证 PC 相关分支
  - 检测分支预测错误
  - 传递指令到 Rename

- **特点**:
  - 指令实际译码在 Fetch 阶段完成
  - Decode 主要做验证工作

### Rename (重命名)

- **主要功能**:
  - 架构寄存器 → 物理寄存器映射
  - 维护 RenameHistory 用于 squash 恢复
  - 处理序列化指令 (barrier)

- **阻塞条件**:
  - ROB 满
  - IQ 满
  - LSQ 满
  - 物理寄存器耗尽

### IEW (Issue/Execute/Writeback)

- **InstructionQueue (IQ)**:
  - 依赖图 (DependencyGraph): 跟踪寄存器依赖
  - 就绪队列 (ReadyInstQueue): 按 OpClass 分类
  - 唤醒机制：生产者完成时唤醒消费者

- **LSQ (Load/Store Queue)**:
  - Load Queue: 加载指令队列
  - Store Queue: 存储指令队列
  - MemDepUnit: 内存依赖预测 (StoreSet)

- **Functional Units**:
  - IntAlu: 整数 ALU
  - FloatAdd/FloatMult: 浮点单元
  - MemRead/MemWrite: 访存单元

### Commit (提交)

- **ROB (Reorder Buffer)**:
  - 维护指令程序顺序
  - 支持乱序执行、按序提交
  - 异常/中断处理

- **主要功能**:
  - 按序提交指令
  - 释放已提交指令的物理寄存器
  - 处理 trap 和中断
  - squash 管理

## 时间缓冲区 (TimeBuffer)

```
TimeBuffer 架构:
┌─────────────────────────────────────────────────────────────┐
│                    TimeBuffer<TimeStruct>                    │
│  ┌─────┬─────┬─────┬─────┬─────┐                           │
│  │  T-2│  T-1│  T  │ T+1 │ T+2 │  ← 时间槽                  │
│  └─────┴─────┴─────┴─────┴─────┘                           │
│      ↑           ↑                                          │
│   读位置      写位置                                         │
└─────────────────────────────────────────────────────────────┘

用途:
• 反向通信：下游级向上游级发送 Stall/Block 信号
• 延迟建模：精确模拟流水线级间延迟
• 时间对齐：确保信号在正确周期到达
```

## IQ 依赖图机制

```
DependencyGraph 数据结构:

物理寄存器 R1:  [Producer: inst_100] → [Consumer: inst_105] → [Consumer: inst_108] → NULL
物理寄存器 R2:  [Producer: inst_102] → [Consumer: inst_110] → NULL
物理寄存器 R3:  NULL (无生产者，无消费者)

唤醒流程:
1. inst_100 执行完成
2. 遍历 R1 的依赖链
3. 唤醒 inst_105 和 inst_108
4. 标记源寄存器就绪
5. 检查指令是否完全就绪，加入就绪队列
```
